# Contributing

Keep changes small and explain the user problem. Run the domain tests and syntax checks before proposing a change. Add meaningful tests when changing expiry or repair/recheck rules.

Preserve synthetic-data labels and do not add private participant information. Document dependencies and their licenses if introduced. Review keyboard interaction and mobile layout for UI changes. Never replace unknown evidence with an optimistic default. Record AI assistance honestly.

Open an issue describing a reproducible problem or submit a pull request with the change and validation. Do not use public issues for sensitive vulnerability details.
