# Security and privacy

This is a synthetic local prototype, not a production identity or safety system. The actor selector and local history are editable by the device owner. Do not use this application to authorize access, dispatch emergency help or certify a route.

The interface inserts text with DOM textContent, uses no third-party scripts and makes no external API/analytics calls. The included loopback server exposes only an explicit file allowlist and sends a restrictive Content Security Policy. Static hosts must configure equivalent headers themselves.

Never submit private IDs, passwords or completed declarations through public issues. For a sensitive vulnerability, use GitHub private vulnerability reporting if enabled; otherwise contact the repository owner privately without posting exploit details or personal data publicly. The repository currently has no guaranteed security response SLA.

Before a real pilot: implement server authorization, independent reviewer identities, audit integrity, consent/retention controls, abuse handling and professional accessibility review.
